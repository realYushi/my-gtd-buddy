# GTD SOP

GTD is five habits held together by one rule: keep commitments out of your head and decide the next action.

## 1. Capture

Put every commitment, idea, and loose end into Inbox. Capture is fast and undecided.

## 2. Clarify

Process one Inbox item at a time:

- Is it actionable?
- No: delete, incubate in Someday, or keep as reference.
- Yes: do it now if it takes under two minutes; otherwise delegate it or define the next physical action.
- Multi-step outcome: make it a project and define its next action.

## 3. Organize

Use five commitments:

- **Inbox**: undecided input
- **Next Actions**: concrete actions ready to do
- **Waiting For**: delegated or blocked work with an owner
- **Someday**: not now, worth revisiting
- **Projects**: outcomes that need more than one action

Contexts such as home, office, errands, and calls narrow the choice. Energy and duration are useful when they reflect the user's real state.

## 4. Reflect

Review often enough to trust the system. The weekly review covers wins, stuck items, project health, waiting items, and a mind sweep.

## 5. Engage

Choose one next action that fits the current context, time, energy, and priority. When overwhelmed, shrink the choice to one thing.

## Decision Tree

```text
Inbox item
├── Not actionable
│   ├── Trash
│   ├── Someday
│   └── Reference
└── Actionable
    ├── Under 2 minutes → do it
    ├── Someone else → Waiting For with owner
    ├── One step → Next Actions with context
    └── Multiple steps → Project + one next action
```

## Invariants

- Inbox is for undecided input.
- Every project has a next action.
- Every waiting item has an owner.
- Every next action starts with a physical action.
- A review states its window and never adds overlapping completion snapshots.
- Unknown values stay unknown.
- Delete and bulk changes require confirmation.
